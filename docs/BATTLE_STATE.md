# 戦闘状態の責務と保存境界

[README](../README.md) · [保存・再開](SAVING.md)

戦闘状態を、同じタイミングで更新・破棄される値と、その更新規則で整理しています。`battle_world.gd` は衝突判定・敵や弾のノード・戦闘ステップの実行順を担当し、数値の更新規則は以下のクラスに委譲します。

## 洗い出しと実装

| 対象 | 所有者 | 更新・参照の規則 |
|---|---|---|
| キル数、敵総数、現在コンボ、残り時間、最大コンボ | `battle_score.gd` | `record_kill()` で撃破とコンボをまとめて更新。`advance()` で失効し、端数を含む追加回収間隔もここで判定 |
| 車体耐久、戦闘経過時間、勝敗、到着先 | `battle_progress.gd` | ダメージの切り上げと下限、到着判定と敗北の優先順位、終了状態の確定を集約。勝敗は名前付き列挙値 |
| 操作入力、実移動速度、速度ベクトル、進行距離、走行軌跡、接触点 | `battle_motion.gd` | 衝突・燃料制限を反映した移動結果から一括更新。回収・地雷判定には壁沿いの経路も含む実際の軌跡を渡す。接触点は適用済みの移動から火花へ渡す |
| 音の前回観測値（工場・戦場ID、製造・射撃・撃破・被弾） | `audio_observation.gd` | 前回と今回の値だけを比較。ロード・ラン変更・時計の巻き戻りを検出し、過去の効果音を再生しない |
| 上記状態の保存と復元 | `run_save.gd`、`run_snapshot_schema.gd` | 各状態クラスの `snapshot()` / `restore()` と `SAVE_FIELDS` を利用し、既存の保存キーに変換 |
| 敵、飛翔体、ドロップ、着弾・履帯などの描画状態 | `battle_world.gd`、`tank_world.gd` | 生存するノード、座標変換、生成・破棄の順序に依存するため、今回の数値状態クラスには含めない |
| ラン全体の進行、所持装備、素材・生産 | `run_state.gd`、`equipment_inventory.gd`、`factory.gd` | 既存の責務を維持。戦闘中の車体耐久とラン間の耐久値は、開始・報酬・修復時にコントローラが引き継ぐ |

HUD・コンボ表示・ミニマップ・効果音は `score` / `progress` / `motion` を参照します。UIからコンボやキル数の加算規則を実行しません。敵の二重撃破防止は敵の生死を扱う `kill_enemy()` の入口に置き、その後でスコアを更新します。

`battle_world.gd` の既存プロパティ（`kills`、`combo`、`hull` など）は、既存シーン呼び出しや回帰テストの互換用アクセサとして残しています。値の実体は状態クラスだけにあり、アクセサ自身は値や更新規則を保持しません。新しい実装からは状態クラスを直接利用します。

## 保存とリセット

状態クラスの導入時は保存形式バージョン11を維持しました。現在はバージョン20で、最新版と移行規則は `run_snapshot_schema.gd` と [SAVING.md](SAVING.md) を参照してください。`battle.kills`、`battle.hull`、`battle.elapsed`、`battle.result`、`battle.distance`、`battle.speed` などのキーを維持し、状態オブジェクトやノードを保存データへ混入させません。

- キル数、耐久値、経過時間、勝敗、進行距離、速度は保存します。
- 敵総数は保存済みの編成から、到着先は保存済みの座標と目的地から再構築します。
- 現在のコンボと残り時間は一時値で、ロード時にリセットします。最大コンボは結果集計のため保存・復元します。
- 押下中の移動入力、速度ベクトル、前フレームの軌跡・接触点、効果音の観測値は引き継ぎません。
- 一時停止中は戦闘ステップを進めず、コンボと経過時間を止めます。
- 同じフレームに致命傷と目的地到着が発生した場合、敗北を優先します。確定済みの結果は再確定しません。

## 検証

`tests/battle_state_test.gd` は描画に依存せず、コンボの時間境界・追加回収間隔・勝敗の優先順位・実移動の記録・音の差分検出を検証します。同ファイルの実戦テストで二重撃破、一時停止、既存形式での保存復元、次ランへの状態漏れも確認します。保存・操縦・HUD・音・装備・通しプレイは既存スイートでも回帰検証します。

```sh
python3 tools/run_tests.py --headless-only --jobs 4 --suite battle_state --suite checkpoint --suite feedback --suite tank_steering
```

独立したテストはヘッドレス・最大4並列で実行します。未対応のUI試験を必要とする場合も、描画待ち・画像取得をヘッドレス対応してから実行し、実ウィンドウを代わりに起動しないでください。


## 自動変速・大破演出

`battle_motion.gd` が `battle_transmission.gd` を所有します。段数と加速率は装備したギアの定義から決まり、実際に停止すると1速に戻ります。移動は最大1/60秒の小刻みなステップで加速と旋回を一緒に適用し、フレーム全体の走行軌跡・接触点を集約します。変速状態は任意の `battle.transmission` に保存し、旧保存は停止・1速で復元します。

HP0の結果集計は従来通り一度だけ状態モデルで確定します。その後、`battle_world` の大破演出時計が3.6秒の連続爆発とカメラを進め、完了後に `result_page` を表示します。メニュー中は演出を停止し、敗北セーブの復帰では爆発を再演せずリザルトを表示します。
